# لمحة POS — حالة التنفيذ

هذه مرحلة تأسيس، وليست نسخة جاهزة للبيع.

## جاهز في الكود
- تسجيل دخول بالبريد وكلمة المرور، دون شاشة تسجيل عام.
- استعادة الجلسة، وخروج من الجهاز الحالي فقط.
- عرض المتاجر بناءً على صلاحيات قاعدة البيانات.
- فصل مدير المنصة عن عضو المتجر في قاعدة البيانات.
- شاشة واضحة عند غياب الإعدادات أو فشل تحميل البيانات.
- إغلاق الوصول إلى واجهة البيع التجريبية؛ ملفاتها لم تُحذف ويمكن تطويرها لاحقًا.

## تشغيل مشروع مستقل
1. أنشئ Supabase جديدًا باسم lamha-pos. الحساب وصل إلى حد مشروعين مجانيين نشطين، لذلك لم ينشأ المشروع.
2. عطّل التسجيل العام من إعدادات Auth قبل إتاحته للمستخدمين.
3. طبّق migration في supabase/migrations على المشروع الجديد فقط.
4. أنشئ حساب مدير المنصة بواسطة Auth Admin API أو Dashboard ثم أضف UUID الخاص به إلى platform_admins من اتصال إداري؛ لا تُحدد صلاحيات المدير بمطابقة البريد في المتصفح.
5. أضف المتاجر وعضوياتها من اتصال إداري. لا يستطيع المستخدم منح نفسه صلاحيات.
6. اضبط متغيرَي .env.example محليًا وفي الاستضافة. استخدم publishable key فقط؛ لا تضع مفاتيح الخدمة في الواجهة أو Git.
7. اختبر حسابين لمتجرين مختلفين وحساب مدير وحساب غير مرتبط؛ تحقق من عزل القراءة والكتابة عبر REST مباشرة، وليس الواجهة وحدها.

## المتبقي
- حساب المدير الحقيقي وتعيين الصلاحيات، إدارة الحسابات بواسطة مدير المنصة.
- منتجات ومبيعات حقيقية، خصم مخزون ذري وتكرار آمن للطلب، مرتجعات ومشتريات وتقارير.
- مراجعة تبعيات النظام والأمان، واختبار RLS فعليًا.
- PWA والنشر واختبار أجهزة فعلية والطباعة.
- توضيح الترخيص: README الأصلي يذكر MIT ولكن المستودع الأصلي لا يحتوي ملف LICENSE.

لم تتغير أي قاعدة بيانات أو استضافة قائمة.

## التحقق في هذه المرحلة
- البناء وTypeScript وESLint للملفات الجديدة: ناجحة.
- 23 assertion على PostgreSQL عبر PGlite: عزل متجرين، منع قراءة مجهول، منع ترقية الصلاحيات، السماح بإدارة المتاجر والعضويات لمدير المنصة.
- اختبار Supabase Auth/REST الحقيقي: لم يجرِ لأن إنشاء المشروع رفض بسبب حد المشاريع المجانية.
- npm audit: 35 تنبيهًا (27 عالية، 5 متوسطة، 3 منخفضة) في التبعيات الموجودة. لم تُنفذ ترقية إجبارية؛ معالجة التبعيات شرط قبل النشر.
