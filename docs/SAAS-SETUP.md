# لمحة POS — حالة التنفيذ

هذه مرحلة تأسيس، وليست نسخة جاهزة للبيع.

## جاهز في الكود
- تسجيل دخول بالبريد وكلمة المرور، دون شاشة تسجيل عام.
- استعادة الجلسة، وخروج من الجهاز الحالي فقط.
- عرض المتاجر بناءً على صلاحيات قاعدة البيانات.
- لوحة مدير المنصة لإضافة متجر وتعديل اسمه وإيقافه بتأكيد وتفعيله، دون حذف بياناته. إعادة محاولة إنشاء المتجر داخل الشاشة تستخدم المعرّف نفسه.
- إدارة حسابات المتاجر للسوبر أدمن: إنشاء حساب ببريد وكلمة مرور، ربط حساب موجود، تغيير الدور وإلغاء الوصول لمتجر محدد بتأكيد.
- إنشاء Auth عبر Edge Function فقط، مع getUser والتحقق من platform_admins من الخادم. التحقق مجددًا في SQL قبل ربط العضوية؛ لا ترسل الواجهة مفاتيح خدمة.
- طلبات إنشاء الحساب محفوظة في جدول private مع بصمة لكشف تغير إعادة المحاولة؛ لا تخزن كلمة المرور نصًا. المتصفح يحفظ بيانات الطلب دون كلمة مرور، ويطلب كلمة المرور الأصلية بعد تحديث الصفحة. لا تعيد إعادة المحاولة عضوية أُلغيت بعد اكتمال الطلب.
- فصل مدير المنصة عن عضو المتجر في قاعدة البيانات.
- شاشة واضحة عند غياب الإعدادات أو فشل تحميل البيانات.
- منتجات وباركود وأسعار وحالة نشاط لكل متجر؛ إنشاء وتعديل للمالك أو مدير المنصة.
- استلام وتسويات مخزون مسجلة بسبب وهوية المنفذ، دون تحرير الرصيد مباشرة.
- بيع ذري: يحتسب الخادم السعر، ويحفظ الفاتورة وخصم المخزون معًا أو يلغي العملية كاملة.
- إعادة محاولة البيع أو حركة المخزون بنفس UUID؛ حفظ الطلب المعلق في المتصفح لاستعادته بعد تحديث الصفحة.
- كميات كسرية حتى ثلاث منازل، وفواتير بلقطات ثابتة لاسم المنتج وسعره وطباعة من المتصفح.
- الكاشير يبيع ويقرأ؛ إدارة المنتجات وتسوية المخزون للمالك أو مدير المنصة فقط.
- الدفع بالبطاقة تسجيل لطريقة السداد فقط؛ لا توجد بوابة دفع.
- ملخص مبيعات للمالك ومدير المنصة: عدد الفواتير وإجمالي البيع وتوزيع النقد والبطاقة من الخادم، لكامل فترة حتى 31 يومًا، حسب توقيت الجهاز. لا يقتصر على آخر 100 فاتورة ولا يمثل صافي الربح.
- manifest وأيقونات تثبيت واسم عربي وRTL ووضع standalone، مع زر التثبيت عندما يتيحه المتصفح وتعليمات إضافة للشاشة الرئيسية. لا يوجد Service Worker أو تخزين API/مبيعات للعمل دون إنترنت.
- ملفات الواجهة التجريبية السابقة لا تستخدم في مسار الحسابات الجديد.

## تشغيل مشروع مستقل
1. المشروع المستقل الذي أرسله المستخدم: grjmagglogyeglsdsiwb، على الحساب الثاني. اتصال الأداة الحالي لا يملك صلاحية إليه؛ يلزم إعادة ربط حساب Supabase قبل التنفيذ الفعلي.
2. عطّل التسجيل العام من إعدادات Auth قبل إتاحته للمستخدمين.
3. طبّق migrations في supabase/migrations بالترتيب على المشروع الجديد فقط. عند تعطيل التعريض التلقائي للجداول، اضبط صلاحيات Data API للجداول والوظائف المطلوبة واختبر REST. الوظائف الخاصة في private لا تُضاف إلى exposed schemas.
4. أنشئ حساب مدير المنصة بواسطة Auth Admin API أو Dashboard ثم أضف UUID الخاص به إلى platform_admins من اتصال إداري؛ لا تُحدد صلاحيات المدير بمطابقة البريد في المتصفح.
5. انشر pos-accounts على المشروع الجديد فقط بعد تطبيق migrations. اضبط POS_ALLOWED_ORIGINS بقائمة أصول HTTPS المسموح بها مفصولة بفاصلة، دون مسارات. SUPABASE_SERVICE_ROLE_KEY يبقى في أسرار الخادم فقط. verify_jwt=true مع فحص getUser داخل الدالة. بعدها أضف المتاجر والحسابات من لوحة السوبر أدمن. config.toml يعطل التسجيل محليًا؛ إعداد المشروع الحقيقي يحتاج التحقق من Dashboard.
   إنشاء الحساب لا يرسل بريدًا، والبريد يُعتمد إداريًا (email_confirm=true). كلمة المرور يحددها المدير؛ لا تُغيّر كلمة مرور حساب موجود ولا تُنهى جلساته. احفظ كلمة المرور الأصلية في مكان موثوق خارج بيانات الطلب في المتصفح إلى أن يكتمل الطلب. إذا تعطل الربط بعد إنشاء Auth قد يبقى حساب دون عضوية، بلا وصول إلى بيانات متجر؛ أعد الطلب نفسه لاستكماله. لا تحذف حساب Auth للتراجع التلقائي.
6. اضبط متغيرَي .env.example محليًا وفي الاستضافة. استخدم publishable key فقط؛ لا تضع مفاتيح الخدمة في الواجهة أو Git.
7. اختبر حسابين لمتجرين مختلفين وحساب مدير وحساب غير مرتبط؛ تحقق من عزل القراءة والكتابة عبر REST مباشرة، وليس الواجهة وحدها.

## المتبقي
- حساب المدير الحقيقي وتعيين الصلاحيات ونشر خدمة الحسابات واختبار Auth الحقيقي، إعداد استعادة/تغيير كلمات المرور والتحقق من جلسات الأجهزة الفعلية.
- تشغيل واختبار مسار المنتجات والمبيعات على Supabase الحقيقي؛ مرتجعات ومشتريات وفواتير ضريبية وتقارير.
- العمل دون إنترنت والمزامنة غير متاحين؛ حفظ طلب معلق ليس نظام بيع offline.
- التخزين المحلي للطلبات يتطلب جهازًا موثوقًا؛ لا تمسح بيانات المتصفح قبل التحقق من طلب معلق.
- مراجعة أمان النظام كاملة واختبار RLS فعليًا؛ فحص التبعيات الحالي لا يغني عن ذلك.
- نشر HTTPS مستقل والتحقق من تثبيت PWA على iPhone وAndroid وأجهزة فعلية والطباعة. التثبيت الفعلي لم يختبر بعد.
- توضيح الترخيص: README الأصلي يذكر MIT ولكن المستودع الأصلي لا يحتوي ملف LICENSE.

لم تتغير أي قاعدة بيانات أو استضافة قائمة.

## التحقق في هذه المرحلة
- البناء وTypeScript وESLint للملفات الجديدة: ناجحة.
- 26 assertion على PostgreSQL عبر PGlite: عزل متجرين، منع قراءة مجهول، منع ترقية الصلاحيات، السماح بإدارة المتاجر والعضويات لمدير المنصة.
- 57 assertion إضافية على PostgreSQL: احتساب السعر من الخادم، rollback لكامل السلة، تكرار آمن، صلاحيات المالك والكاشير، فصل المتاجر، ثبات بيانات الفاتورة وملخص أكثر من 100 فاتورة وحدود التواريخ وصلاحية الملخص. الاختبارات بجلسة واحدة؛ تزامن جلسات حقيقية يحتاج اختبارًا بعد الربط.
- فحص متصفح محلي بواجهات API وهمية: تسجيل الدخول، استعادة طلب البيع والمخزون بعد تحديث الصفحة، إنشاء متجر مع فقد الاستجابة وإعادة المحاولة، تعديل الاسم، تأكيد الإيقاف والتفعيل. اختبار manifest والأيقونات وحدث تثبيت محاكى وتنبيه انقطاع الاتصال وملخص المبيعات وتوقيت الرياض وحد الفترة. تحقق عدم تجاوز عرض الشاشة عند 390/768/1440 بكسل. هذا ليس اختبار Supabase الحقيقي أو جهاز جوال فعلي.
- 38 assertion لخادم الحسابات باستخدام Auth/DB وهميين، و25 assertion إضافية على PostgreSQL: منع وصول المتصفح لعمليات الخدمة، عزل قائمة الحسابات، تعارض الأدوار والطلبات، إلغاء العضوية ثم إعادة الطلب، تعطيل المتجر وسحب صلاحية المدير.
- فحص متصفح إضافي: إنشاء حساب مع فقد الاستجابة وإعادة الطلب بعد تحديث الصفحة، عدم حفظ كلمة المرور، تغيير الدور وتأكيد إلغاء الوصول.
- Deno check لخادم الحسابات: ناجح. لم تُنشأ حسابات فعلية أو يُرسل بريد.
- اختبار Supabase Auth/REST الحقيقي: لم يجرِ؛ المشروع الجديد في الحساب الثاني غير متاح للاتصال الحالي.
- npm audit: صفر تنبيهات معروفة وقت التحقق، بعد تحديث التبعيات وVite 7 وReact Router 7 وTailwind 4 وحذف lovable-tagger. لا يعني ذلك ضمان غياب الثغرات.
- CI يعيد فحوص PostgreSQL والمتصفح والبناء والتبعيات. Node >=22.12 مطلوب.
- التصميم بعد Tailwind 4 يستهدف متصفحات حديثة: Safari 16.4+ وChrome 111+ وFirefox 128+؛ الأجهزة الأقدم تحتاج تقييمًا منفصلًا. لم يتحقق اختبار الطابعة أو أجهزة فعلية.
